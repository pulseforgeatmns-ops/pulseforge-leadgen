## Context

Scout discovery depends on external sensors — Google Places, LinkedIn, registries, email verification, review scraping, and future providers. Each sensor produces observational telemetry about its own execution: HTTP status, provider-specific status codes, latency, query text, result counts, and failure reasons.

AUDIT-060 demonstrated that this telemetry was generated correctly but dropped at the Discovery contribution normalization boundary. Operators saw generic validation messages (`Contribution must attach evidence.`) with no sensor context, even when Places had executed and returned `REQUEST_DENIED` or `ZERO_RESULTS`.

## Decision

**Observations generated by system sensors are first-class evidence about system execution and shall remain observable throughout the execution lifecycle, even when business execution fails.**

Concretely:

1. `providerExecution` is part of the canonical Discovery contribution contract.
2. No stage may remove provider execution telemetry before persistence.
3. Provider telemetry is **observational only** — it must never influence business reasoning, scoring, or qualification.
4. Validation failures must still attach provider diagnostics to the execution result for operator explainability.
5. Presentation must render provider execution when Discovery fails or returns zero qualified prospects.

## Consequences

### Positive

- Operators can distinguish "Places returned zero results" from "Places was never called" from "API key denied."
- Rollback inspection retains sensor context in error details even when TME rolls back the mission store.
- Future providers (LinkedIn, registries, email verification) follow the same continuity contract.

### Negative / constraints

- Discovery contributions carry additional observational payload — bounded to provider report count per run.
- Presentation prose grows when providers fail; this is intentional for operational visibility.

## Invariants

| Invariant | Enforcement |
|---|---|
| Sensor observations survive normalization | `DiscoveryPayload.normalizeScoutDiscoveryPayload()` |
| Sensor observations persist with mission | TME `commitDiscoveryStage()` |
| Sensor observations survive rollback inspection | `TransactionalExecution` attaches diagnostics to validation errors |
| Sensor observations are not business evidence | `assertEvidenceAttached()` ignores `providerExecution` |
| Sensor observations render for operators | `DiscoveryPresentation.formatDiscoveryResultsLines()` |
