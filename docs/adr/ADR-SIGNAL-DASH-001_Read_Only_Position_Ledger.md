# ADR-SIGNAL-DASH-001 — Read-only position ledger

Decision: keep real operator positions separate from Signal paper/research state. Append immutable raw wallet transactions and market/event evidence in a tenant+wallet scope. Store lot calculations as deterministic projections, never as empirical facts. Fixed decimal BigInt arithmetic avoids binary-float accounting drift. Timestamp ordering is block time, slot and transaction index; ambiguous same-slot order makes accounting partial. Unknown acquisition basis or consideration propagates to P&L.

The collector is a separate process; web reads never call chain/market providers. A deployment-wide PostgreSQL budget and advisory lock bound each collector. UI polling recovers without a page refresh. The API is owner/role scoped, uses persisted observations, has no execution surface, and returns no credentials. Operator annotations are separate records and cannot alter evidence. Known-at filtering prevents importing later risk or price evidence into a historical marker. Public provider caching is disclosed; polling frequency is not proof of market freshness.

Alternatives: reuse paper positions (rejected: confuses simulated and real funds); provider calls on page loads (rejected: duplicated requests, latency and quota); infer trades from screenshots (rejected: chain is canonical); native wallet balance deltas as swap proceeds (rejected: rent, fees and unrelated transfers make this ambiguous).

The isolated deployment may reuse existing Pulseforge credentials by verifying the configured owner's existing user row. It maintains separate Signal session and login-attempt tables and checks revocation on each protected request. Public RPC is the default wallet adapter; verified PumpSwap instructions and exact net SPL balance changes support native USDC accounting, with other programs/quote legs remaining partial or unknown. Independent collector locks keep chain backfill latency from blocking market updates. No core service redeploy is required.
