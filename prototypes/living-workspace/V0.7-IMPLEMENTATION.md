# Living Workspace V0.7 — Adaptive Composition, Bounded Spatial Context, and Layout Lock

Status: implementation contract; prototype only. Branch: `feat/living-workspace-foundation`.
Scope: `prototypes/living-workspace/` only. Do not deploy, merge to production, wire production APIs, or alter P0 Max/Scout behavior.

## Product invariants
1. Operations is the default lens. Entities and Objectives are optional user-selected lenses, not mandatory modes or separate dashboards.
2. The spatial field represents a bounded **working context**, not all known business entities. Large datasets must aggregate, filter, search and progressively disclose. Never draw one node per client at portfolio scale.
3. A lens changes presentation and emphasis over the same selected entity, history and shared panel context. Switching lenses must not reset selection or automatically rearrange panels.
4. Users may choose the displayed lens, filtered working set, panel arrangement and saved composition. Max can suggest changes; it must not silently override explicit choices.
5. A layout lock protects composition (panel geometry, order, docking, visibility, field allocation), not content (selection, panel data, searches, spatial pan/zoom).
6. Max and direct manipulation must use the same lock-aware dispatcher. UI-only disabled handles are insufficient.
7. All tests and demos use fictional fixture data and simulated Max. No live model calls.

## V0.7 implementation sequence
### A. Lock-aware composition model and dispatcher
- Extend existing V0.6 state/store, do not create a competing state store.
- Track lock state per tenant and saved composition, with a protected composition revision.
- Add explicit lock/unlock commands and reject layout-mutating commands while locked, including batch commands, history restore, and Max simulated rearrangements.
- Keep navigation, selection, search, panel content refresh, field pan/zoom, and lens changes available.
- Distinguish navigation history from layout history. Undo/redo must not bypass a lock.
- A blocked command returns an explicit structured reason, with no partial mutation.
- Locked composition persistence must survive reload and tenant switching; failed saves must not claim success.
- Allow an explicitly approved temporary copy of a locked composition; preserve the original. Any unlock-and-modify request must be confirmed against the current tenant, composition and revision.

### B. Visible UI
- Add a clearly labeled Lock/Unlock control near existing Layouts controls with accessible state and keyboard/touch support.
- Disable or safely intercept splitter dragging, panel resizing, docking, minimizing and closing while locked.
- New tools in locked mode should use a temporary overlay or existing dock surface without displacing protected panels.
- Responsive projections may adapt to viewport but must not overwrite saved logical geometry. Returning to the original viewport restores the intended composition.

### C. Bounded working context and optional lenses
- Operations overview stays default; aggregate priorities, objectives, attention and domain status.
- Entities lens starts with search, filters, and a small relevant working set. Select a company to progressively expand contacts, evidence, activities and relationships. Do not enumerate the full client universe as nodes.
- Objectives lens shows active goals, dependencies, blockers, owners and related entities from fixtures.
- Introduce a bounded node budget with explicit overflow/aggregate affordance and list/search fallback. Ensure counts represent total matches rather than only visible nodes.
- Lens changes must preserve shared selection and following/pinned panel behavior. They may change spatial node placement, not workspace panel composition.
- Support manual control of the lens and filters. Simulated Max can propose context, but should not automatically change lens against user preference.

### D. Verification
- Existing V0.6 tests continue to pass.
- Add unit tests for locked mutations, atomic batch rejection, undo/redo, persistence, tenant separation, temporary copy, lens preservation, filtering and overflow.
- Add browser/touch tests for visible lock state, splitter prevention, optional lenses, search/filtered entities, selection continuity, responsive restoration and Max lock enforcement.
- Explicitly exercise fixture scale (e.g. 2,000 companies / 15,000 contacts) without rendering thousands of nodes; measure visible node count and responsiveness.
- Report commit SHA, tests executed and pass/fail counts, known issues, screenshots/behavior checks, and confirmation that no production files changed.

## UX acceptance
- A user who likes their arrangement can lock it and safely navigate business information without it moving.
- A user with thousands of clients can still quickly find one by search, or investigate a short priority working set.
- A user who never chooses a lens can continue working in Operations normally.
- Max can update context inside existing panels without changing their arrangement; when a requested change conflicts with the lock, it asks for an explicit choice rather than unlocking silently.
